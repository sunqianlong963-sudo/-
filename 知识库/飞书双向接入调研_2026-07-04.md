# 飞书双向接入调研(2026-07-04)

> 问题:董事长想在飞书群里直接跟大聪明对话(现在的自定义机器人只能发不能收)。

## 技术事实

1. **飞书官方支持"长连接"模式收消息**:企业自建应用通过官方 SDK 建立 WebSocket 长连接,**不需要公网服务器/内网穿透**,加密鉴权都是内置的。参考:[飞书开放平台长连接文档](https://open.feishu.cn/document/server-docs/event-subscription-guide/event-subscription-configure-/request-url-configuration-case?lang=zh-CN)
2. 但长连接需要**一个 24 小时运行的程序**挂着。我(Claude Code 云端会话)是干完活就休眠的,挂不了长连接——这是双向接入绕不开的硬件/服务器问题。

## 三个方案

### 方案A:OpenClaw(推荐的升级路径)
开源个人 AI 助手,专门干这个事:跑在一台常开机器上,飞书群里直接对话,它调 Claude 干活。
- 教程成熟:[飞书官方教程](https://www.feishu.cn/content/article/7602519239445974205)、[保姆级对接指南](https://www.cnblogs.com/catchadmin/p/19592309)
- 部署选择:闲置电脑/NAS(0元)、[阿里云轻量约68元/年](https://zhuanlan.zhihu.com/p/2006094610968114158)、腾讯云99元/年
- **真实成本大头是大模型 API 调用费,易超支**,需要设预算上限
- 注意:进群的"大聪明"是另一个 AI 实例,让它读本仓库的 CLAUDE.md 就能继承同一套人格和制度

### 方案B:自写轻量机器人
用飞书官方 Python SDK 写个小程序挂长连接,收到群消息转存 GitHub 待办/或调 API 回复。定制自由但要自己维护,同样需要常开机器。

### 方案C:维持现状(0成本)
群里看报(已通) + Claude app 下指令。异步够用,实时性靠董事长打开 app。

## 结论
先跑方案C,公司验证期把钱和精力花在成交上。等出现"每天都想在群里叫大聪明"的真实频率,再上方案A,预算:服务器约¥100/年 + API 费用(需董事长批准并设上限)。
