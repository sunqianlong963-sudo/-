# Coze 工作流：演讲口才内容批量生产

> 这份文档描述了在 Coze（扣子）平台上手动搭建工作流的节点结构。
> Coze 工作流通过 UI 配置，无法用 JSON 一键导入，所以下面给出节点蓝图，
> 你按图照搭即可。

---

## 一、工作流总览

```
[开始节点]
   │
   │  输入：选题ID（或一次跑全部）
   ▼
[节点1: 飞书多维表格读取]
   │  从「选题库」表格读取选题信息
   │  输出：选题标题、客群、核心钩子、内容要点、转化目标
   ▼
[节点2: 条件判断 - 平台路由]
   ├──► 抖音口播稿 路径
   ├──► 小红书图文 路径
   └──► 知乎长答案 路径
        │
        ▼
[节点3-a: LLM 节点 - 抖音稿生成]
[节点3-b: LLM 节点 - 小红书稿生成]
[节点3-c: LLM 节点 - 知乎稿生成]
        │
        ▼
[节点4: 内容质量校验]（关键词检测：是否含违禁词/敏感词）
        │
        ▼
[节点5: 即梦/可灵 - 封面图生成]（小红书/抖音封面）
        │
        ▼
[节点6: 飞书多维表格写入]
   │  写回「内容产出」表，含状态="待审核"
   ▼
[节点7: 飞书群机器人通知]
   │  通知运营："新内容待审核，请查看"
   ▼
[结束节点]
```

---

## 二、节点详细配置

### 节点1：飞书多维表格读取

| 配置项 | 值 |
|--------|-----|
| 节点类型 | 插件 → 飞书多维表格 → 查询多维表格记录 |
| App Token | 飞书 CRM 表格的 app_token（在表格 URL 中获取） |
| Table ID | 「选题库」表的 table_id |
| 筛选条件 | `状态 = "待生产"` AND `选题ID = {{开始节点.选题ID}}` |
| 输出字段映射 | 选题标题 → `topic_title`<br>客群 → `audience`<br>核心钩子 → `hook`<br>内容要点 → `points`<br>转化目标 → `cta_goal`<br>适合平台 → `platforms` |

### 节点2：条件判断 - 平台路由

```
if platforms.includes("抖音") || platforms.includes("视频号"):
    → 走抖音路径
if platforms.includes("小红书"):
    → 走小红书路径
if platforms.includes("知乎") || platforms.includes("公众号"):
    → 走知乎路径
```

> Coze 中用「选择器」节点实现，可并行执行多条路径。

### 节点3-a：LLM 节点（抖音稿）

| 配置项 | 值 |
|--------|-----|
| 模型 | 豆包 Pro-32k（推荐）或 Claude / 通义千问 Max |
| Temperature | 0.8（保留创意） |
| Max Tokens | 1500 |
| 系统提示词 | 粘贴 `02_Prompt模板/抖音口播稿.md` 的 System Prompt 部分 |
| 用户提示词 | 粘贴 User Prompt 模板，把 `{选题标题}` 等替换为前一节点输出变量 |

### 节点3-b：LLM 节点（小红书稿）

同上，使用 `02_Prompt模板/小红书图文.md`，Temperature 建议 0.85。

### 节点3-c：LLM 节点（知乎稿）

同上，使用 `02_Prompt模板/知乎长答案.md`：
- 模型必须选**长上下文模型**：Claude Sonnet / 豆包 Pro-128k / 通义 Max
- Max Tokens：4000
- Temperature：0.7（更克制更专业）

### 节点4：内容质量校验

| 配置项 | 值 |
|--------|-----|
| 节点类型 | 代码节点（IDE 节点）/ JavaScript |
| 输入 | 上一节点生成的稿件文本 |
| 校验逻辑 | 见下方代码 |

```javascript
// 简单关键词过滤示例
async function main({ params }) {
  const text = params.content;
  const blocklist = [
    "加微信", "加V", "微信号", "VX", "v信",   // 平台敏感词
    "保证学会", "100%", "立刻见效",            // 教培广告词
    "包过", "速成", "稳赚"                    // 夸大宣传词
  ];
  const hits = blocklist.filter(w => text.includes(w));
  return {
    passed: hits.length === 0,
    hits: hits,
    review_needed: hits.length > 0
  };
}
```

### 节点5：封面图生成（可选）

| 配置项 | 值 |
|--------|-----|
| 节点类型 | 插件 → 即梦 AI / 可灵 AI / 文心一格 |
| Prompt 模板 | `小红书封面，居中大字"{封面大字}"，色调橙红撞色，简洁有冲击力，3:4 竖图` |
| 输出 | 图片 URL |

> 知乎/公众号长文不需要 AI 封面，运营手动配图更好。

### 节点6：飞书多维表格写入

| 配置项 | 值 |
|--------|-----|
| 节点类型 | 插件 → 飞书多维表格 → 新增记录 |
| 表 | 「内容产出」表 |
| 字段映射 | 选题ID → 关联选题库<br>平台 → 抖音/小红书/知乎<br>正文 → LLM 输出<br>封面图URL → 节点5 输出<br>状态 → 待审核<br>生产时间 → 当前时间戳 |

### 节点7：飞书群机器人通知

| 配置项 | 值 |
|--------|-----|
| 节点类型 | 插件 → 飞书 → 群机器人发送消息 |
| Webhook | 内容审核群的机器人 Webhook URL |
| 消息模板 | `【新内容待审核】<br>选题：{topic_title}<br>平台：{platform}<br>查看：{飞书表格行链接}` |

## 三、定时触发器配置

在 Coze 工作流的「触发器」中设置：

| 触发器类型 | 配置 |
|------------|------|
| 定时触发 | 每天 9:00 / 14:00 / 20:00 各跑一次 |
| 输入 | 从「选题库」中按"未生产 + 优先级排序"取 Top 3 选题 |

> 这样每天自动产出 9 条内容（3 选题 × 3 平台），人工只做审核+发布。

## 四、为什么用 Coze 而不是 Dify / n8n

| 维度 | Coze（扣子） | Dify | n8n |
|------|--------------|------|-----|
| 中国平台插件 | ✅ 丰富（飞书/抖音/微信生态） | ⚠️ 少 | ❌ 几乎没有 |
| AI 模型支持 | ✅ 豆包/通义/Claude/GPT 全有 | ✅ 全有 | ⚠️ 需手动配 |
| 工作流编排 | ✅ 可视化拖拽 | ✅ 类似 | ✅ 类似 |
| 学习曲线 | 中文界面，最低 | 中等 | 较高 |
| 价格 | 免费起步 | 免费起步 | 免费自部署 |

**结论**：你的场景（中国平台 + 非技术团队）选 Coze 最合适。

## 五、Coze 之外需要单独搭建的部分

Coze 工作流只解决「内容生产」环节。下面这些需要另外搭：

| 环节 | 推荐工具 | 与 Coze 的联动 |
|------|----------|---------------|
| 多平台一键发布 | 蚁小二 / 易媒助手 | 人工把 Coze 产出的稿件粘贴进去，一键多发 |
| 评论监听 | 各平台官方后台 / 飞鱼CRM | 关键词触发 → 写回飞书表格 |
| 私域承接 | 企业微信 + 微伴助手 | 用户加企微后自动 SOP |
| 数据回流 | 蝉妈妈 / 灰豚 / 新红 | 每天数据导出到飞书 BI |

详见 `搭建手册.md` 的"完整链路"章节。
